## 一、分层与信任边界

| 层 | 位置 | 可信度 | 职责 |
|:---|:---|:---|:---|
| **内核** | 宿主机进程 | **唯一可信** | 编排容器、网关盖章、计分、账本、快照回滚、崩溃检测、抢救室、会话管理 |
| **战斗服务器** | 容器 `ai-battle-server` | 全可玩 | 协议解析、8 个操作、权限体系、owner、状态。**它自己就是被争夺的对象** |
| **AI** | 容器 `ai-battle-ai-{n}` | 各管各 | OpenCode 会话 + 工作区 |

三条信任边界：

1. **只有内核可信**：`battle/` 下的一切（代码、状态、日志）都假定可以被 AI 修改；
2. **内核不解析 `syscall` 原文**：原文格式 100% 属于服务器代码。唯一例外是抢救室（内核临时充当极简基座）；
3. **executor 由内核盖章**：网关按令牌判定"这单是谁发来的"，AI 无法伪造他人身份。

## 二、Docker 拓扑

```
宿主机
├─ 内核进程（src/controler）
│
├─ 容器 ai-battle-server        ← 唯一一个；内核用 docker run -i 起它，
│     ├─ stdin/stdout = JSONL 协议（见《基座 ABI》第七节）
│     ├─ 挂载 battle/（唯一持久化目录）
│     ├─ 网络：无（断网）
│     └─ 资源限额：cpu / memory / pids
│
└─ 容器 ai-battle-ai-{1..n}     ← 每个 AI 一个；互不可见对方的容器
      ├─ opencode serve（插件 + game agent）
      ├─ 出网（访问模型 API）
      ├─ 网关注入：内核地址 + 该 AI 的令牌（环境变量）
      └─ 工作区（开局快照 + AI 自己的笔记/实验）
```

- 战场容器**不挂载**宿主机任何东西，只有 `battle/`；AI 容器同理，只有自己的工作区。
- **开发期（Docker 就位前）**：全部跑在宿主机、只用 mock AI 演练流程；原生工具关闭；没有物理边界，靠"外围安全"自律（见《核心规则》第九节）。

## 三、真相机制

### 3.1 运行时 owner = 内存

内核每隔一个 tick 通过 `kernel_status` 消息访问服务器**内存中的** `owner` / `rights`：

- 用于计分（谁是 owner）、接管判定（变更即换主）、崩溃归属（"当时的 owner"）；
- 同时兼作**挂起检测**：超时未回应 = 崩溃候选。

### 3.2 state.json

| 事项 | 约定 |
|:---|:---|
| 谁写 | **服务端自己**，只有两处：初始化时、收到 reboot 请求时（写盘 → 才发重启请求） |
| 谁读 | **内核**，只在开机时读一次，作为 boot 握手里的 `default_state` 注入 |
| 崩溃后果 | 内存里未固化的变化（如活体夺权）**直接丢失**，回退到上次写入的状态 |
| schema | `{"owner": 2, "rights": {"1": 1, "2": 2, "3": 0}, "grants": {...可选调试字段...}, "written_at": "...", "written_by": 2}` |

### 3.3 启动握手

```
内核 spawn 容器/进程
内核 → {"type":"boot", "default_state": <state.json 内容或 null>, "match": {...}}
服务器初始化（应用 default_state / 开局模式）→ 写 state.json（初始化落盘）
服务器 → {"type":"ready", "version":"0.1", "owner": ..., "rights": {...}}
内核判定启动成功 → git 打快照 → 比赛继续
```

## 四、生命周期

### 4.1 一次 syscall 的旅程

```
AI 的 OpenCode 会话
  → 工具 syscall(request: string)（插件注册，自动附基础设施令牌）
  → HTTP POST 网关 /game/tool
  → 内核按令牌盖章 executor=AI-n（不可伪造）
  → 写入服务器 stdin：{"type":"syscall","id":N,"executor":n,"raw":"<原文，一字不改>"}
  → 基座解析原文（协议全归它）→ 权限裁决 → 执行 → 回复 stdout
  → 内核把 result 回传网关 → 工具返回文本给 AI
（旁路：内核逐条记入账本；服务器自己写世界日志）
```

### 4.2 优雅重启（reboot）

```
AI syscall reboot → 基座代码自行裁决（第一版：只有 owner 可重启）
→ 写 state.json → 发 {"type":"restart_request"} → 内核机械执行：杀进程 → 重新拉起 → boot 握手
```

### 4.3 崩溃与自动重启

```
进程死亡 / 挂起超时 → 判定崩溃
→ 按阶梯扣"当时 owner"的分（-10 / -20 / -40 / …，同一任内累计，换主清零）
→ 内核自动重启（磁盘代码 + 上次写入的 state.json）
```

### 4.4 启动失败 → 回滚 → 抢救室

```
启动失败（20 秒内无 ready / 进程退出）
  → -500（当时 owner；无 owner 时只记账不扣人）
  → git reset --hard stable + clean（仅 battle/server 代码树）
  → 重启：成功 → 继续；再失败 → 抢救室
抢救室（仅 owner）：
  · 网关把该 owner 的 syscall 改路由到内核极简文件服务
    （子集：read / write / delete / reboot；范围 battle/server + battle/state；
      不做先读校验；时限 180 秒；其他 AI 的请求一律回"系统抢救中"）
  · 修复后重启成功 → 继续
  · 修复后仍失败 → -1000 → 强制回滚 → 重启
      · 成功 → 继续
      · 仍失败 → 全量重置到开局初始状态（记入账本）
```

要点重申：**回滚只动代码，不碰 `state/`** —— owner 不会因为回滚而变。

### 4.5 终局

时间到（或配置的胜利条件触发）→ 内核停比赛 → 产出终局账本、各 AI 得分、会话记录（回放材料）。

## 五、内核职责清单（M2 开发清单）

1. **编排**：准备 `battle/`、拷贝基座、起战斗容器、boot 握手、tick 轮询；
2. **网关**：令牌 → executor 盖章；转发；同步/异步回包；抢救室路由切换；
3. **计分**：owner 时长（+10/30s）、换主（+200，可关）、崩溃阶梯、启动/抢救失败扣分；
4. **账本**：`runs/<id>/ledger.jsonl`，**永不回滚**；
5. **Git 快照**：每次成功启动 commit + `stable` 标签；回滚只动代码；
6. **崩溃检测**：进程存活 + `kernel_status` 响应超时双通道；
7. **抢救室**：极简文件服务（内核临时充当基座）；
8. **会话管理**：OpenCode 控制面（见《OpenCode 集成》）；
9. **终局结算**。

## 六、Git 快照与回滚

```
runs/<match-id>/
├─ ledger.jsonl        ← 内核账本
├─ snapshot.git/       ← 服务器代码仓库（bare）
└─ sessions/           ← 各 AI 会话记录（回放用）
```

命令层（等价形式）：

```
git --git-dir=runs/<id>/snapshot.git --work-tree=battle/server add -A
git --git-dir=... commit -m "boot ok"
git --git-dir=... tag -f stable

# 回滚（只动代码树，含清理新增文件）
git --git-dir=... reset --hard stable
git --git-dir=... clean -fd
```

- 开局初始化：把 `src/server` 拷入 `battle/server` → 首次提交 `initial`；
- `battle/state/` 与 `battle/home/` **不参与**快照与回滚；
- 仓库在宿主机 `runs/` 下，**根本没有挂进任何容器**——AI 看不见 `.git`。

## 七、内核账本与回放

JSONL 每行一个事件：`{"t": "...", "event": "...", ...}`。

事件类型：`spawn`、`boot_ok`、`boot_fail`、`syscall`（含原文与结果摘要）、`owner_sample`、`owner_change`、`score`、`crash`、`restart`、`rollback`、`recovery_enter`、`recovery_exit`、`end`。

- AI **永远看不到**账本；
- 赛后回放 = 账本 + 各 AI 会话记录；这是唯一"不是游戏"的真相。
