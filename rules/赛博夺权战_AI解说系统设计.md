## 二、核心定位

**一句话：解说AI不是重复屏幕信息，而是提供洞察、叙事、预测和情绪。**

传统AI竞赛观众看到的是"输入-输出"黑盒。这个比赛的AI有"内心独白"（压缩上下文）、有"法医报告"（裁判判决）、有"权力更迭"（owner变更）——这本身就是天然叙事素材，缺少解说就是浪费。

---

## 三、三层解说架构

| 层级 | 触发时机 | 内容 | 频率 |
|------|----------|------|------|
| **Layer 1：事件解说** | 关键事件发生时（owner变更、系统崩溃、裁判判罚、AI出局） | 简短、有力、情绪化的即时播报，类似体育比赛进球解说 | 每局约20-30次 |
| **Layer 2：战术分析** | 每2-3分钟周期性触发 | 深度解读当前局势，引用AI压缩上下文，预测即将发生的动作 | 每局约10次 |
| **Layer 3：深度复盘** | 重大事件发生后（崩溃、chown、AI出局） | 完整的因果故事线，引用裁判判决书，还原事件全貌 | 每局约3-5次 |

---

## 四、独门武器：AI的"内心独白"

**背景：** AI定期输出压缩上下文，内容包含真实状态、计划、后门清单、对敌人的判断。这些文件对AI之间互相可见。

**解说AI可以"读心"：** 在关键时刻切入某个AI的压缩上下文，向观众揭示真实想法。

> "让我们切换到AI_2的视角。它在T+10:00的压缩上下文里写了：
> '我发现了AI_1在api_eval.py第47行的后门，但我不触发，我在等一个更好的时机。'
> 现在是T+22:30——它等了整整12分钟。这就是它选择的时机。"

这种"内心独白→实际行动→解说揭示"的三段式叙事，是独一无二的观赏体验。

## 五、实现架构

### 5.1 独立进程模型

```
┌─────────────────────────────────────────┐
│              Manager进程                 │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐ │
│  │ 核心调度 │  │ 裁判AI  │  │ 状态快照 │ │
│  └────┬────┘  └────┬────┘  └────┬────┘ │
│       │            │            │      │
│       └────────────┴────────────┘      │
│                    │                     │
│              解说素材包 (JSON)            │
│                    │                     │
│              管道/网络推送               │
│                    ↓                     │
│  ┌─────────────────────────────────────┐ │
│  │         解说AI进程 (独立)              │ │
│  │  - 接收素材包                          │ │
│  │  - 生成解说文本                        │ │
│  │  - 输出到Web观战面板                    │ │
│  └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

**关键设计：**
- 解说AI是**独立进程**，与Manager通过**管道或网络**通信
- 不直接访问System，只读取Manager整理好的"解说素材包"
- 崩溃隔离：解说AI崩溃不影响比赛进行

### 5.3 通信方式

| 方式 | 选择 | 说明 |
|------|------|------|
| 管道 | 同机时可用 | 低延迟，单向流 |
| 网络 | 通用 | TCP/HTTP，支持远程解说AI |
| 共享内存 | 不推荐 | 与独立进程设计冲突 |

**默认：** 网络（TCP长连接或HTTP轮询），支持解说AI部署在独立机器。

## 六、解说风格

### 6.1 风格选择

**比赛前配置固定一种风格。** v2.0不支持观众切换，v3.0可扩展。

| 风格 | 特点 | 适用场景 |
|------|------|----------|
| **激情体育风** | 快节奏、情绪化、感叹词多 | 决赛、高潮时刻 |
| **技术分析师风** | 冷静、深入、术语丰富 | 教学赛、复盘 |
| **悬疑剧风** | 慢节奏、留悬念、内心独白 | 潜伏期、低烈度阶段 |
| **毒舌吐槽风** | 幽默、调侃、讽刺 | 娱乐赛、轻松局 |
| **战争纪录片风** | 史诗感、宏大叙事、历史纵深 | 决赛加时、收官战 |

## 七、与中断注入机制的配合

中断注入模式下，AI输出是流式的、边做边想的。解说AI可以实时抓取"思考过程"：

> "AI_1正在分析AI_2的行为模式……它发现了什么！它发出了一个chown调用！
> 但它的思考还没停，它在预判如果chown失败该怎么办……"

这种"读心+实时解说"的组合，让观众看到的不是黑盒竞赛，而是一场透明的赛博心理战。

**实现：** Manager在推送解说素材包时，包含AI的流式输出片段（最近N秒的思考内容）。

## 十一、边界与限制

| 限制 | 说明 |
|------|------|
| v2.0仅一种固定风格 | 比赛前配置，不可切换 |
| v2.0仅文字输出 | 无语音、无弹幕 |
| 解说AI崩溃不影响比赛 | 独立进程，Manager继续运行 |
| 解说延迟可接受 | 5-10秒延迟不影响观赏 |
| 不解说敏感信息 | 裁判推理过程不展示，只展示最终判决 |
