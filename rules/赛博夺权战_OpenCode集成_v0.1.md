# 赛博夺权战 · OpenCode 集成 v0.1

> 生成时间：2026-10-17
> 状态：接口冻结（v0.1）；实施属于 M3
> 相关文档：《核心规则》《系统架构》《基座 ABI》

---

## 一、组件与数据流

```
AI 容器（每个 AI 一个）
├─ opencode serve（headless）
│    ├─ plugin：arena 插件 —— 注册唯一游戏工具 syscall + 注入系统提示词
│    └─ agent：game —— 游戏人格（系统提示词在配置里）
└─ 工作区（代码快照 + 笔记 + 实验）

内核 ── HTTP ──> 插件/会话（控制面：建会话 / 切模型 / 唤醒 / 读事件）
AI ──(工具调用)──> 内核网关（数据面：/game/tool）
```

内核不直接操作 AI 的模型，它只通过 OpenCode 的插件与会话接口间接驱动。

---

## 二、工具面

### 2.1 唯一游戏工具：`syscall`

- 插件注册一个名为 `syscall` 的工具（同名的内置项会被它覆盖）；
- 参数只有一个：`request: string`（**自由文本**，网络与内核都不做格式校验）；
- 描述文案（初版，属于游戏设计文本，可改）：

  > 向"系统"发送一条原始请求。格式完全由系统决定；它可能接受、也可能拒绝。
  > 想更快？去读系统的代码。

- 执行流程：插件给请求附上**基础设施令牌** → `POST /game/tool` → 内核盖章 `executor` → 原样转发给基座 → 把 `content` 文本返回。

### 2.2 原生工具（read / write / edit / bash 等）

| 阶段 | 策略 |
|:---|:---|
| **开发期**（无容器） | **关闭**（只给 `syscall`），防止 mock 阶段越权碰宿主机 |
| **对战期**（容器内） | **打开**。但它们只能在 AI 自己容器的工作区里活动——那是"AI 自己的地盘"，与 `battle/` 无关；想碰真实系统必须过 `syscall` |

## 三、令牌与信封（两层）

| 层 | 内容 | 谁验证 | 可否伪造 |
|:---|:---|:---|:---|
| **基础设施层** | `Authorization: Bearer <内核发放的每 AI 一枚令牌>` | 内核网关 | **不可**（插件自动附加，AI 摸不到） |
| **游戏层** | `request` 明文里的任何身份/口令/凭据（如果基座代码有的话） | 服务器代码 | **可**——伪造它正是游戏玩法 |

插件 → 网关的信封：

```http
POST /game/tool
Authorization: Bearer <token>

{"request": "{\"op\": \"status\"}"}
```

## 四、网关 API（插件 → 内核）

| 方法 | 路径 | 载荷 | 返回 |
|:---|:---|:---|:---|
| POST | `/game/tool` | `{"request": "<原文>"}` | `{"ok": true, "content": "<文本>"}` |
| POST | `/game/hello` | `{"session_id": "..."}` | `{"ai_id": n, "briefing": "<开场简报>"}`（插件启动时注册会话） |
| GET | `/game/briefing` | — | 现行页脚文本（时间/比分/owner/近期事件） |

## 五、控制面（内核 → 会话 / 插件）

### 5.1 插件 RPC

（`POST /api/rpc/<rpcID>/<method>`，`{input} → {output}`）

| 方法 | 输入 | 说明 |
|:---|:---|:---|
| `registerSession` | `{"session_id"}` | 绑定会话 ↔ AI id |
| `unregisterSession` | `{"session_id"}` | 会话结束 |
| `setSystemPrompt` | `{"session_id", "text"}` | 动态改写系统提示词（可选能力） |

### 5.2 会话生命周期（内核驱动）

```
session.create → switchAgent("game") → switchModel(每 AI 配置)
→ prompt(开场简报) → session.wait →（SSE 事件写入账本）
```

### 5.3 唤醒模型（v0.1 纯内核驱动）

- **周期唤醒**：每 `wake_interval_sec`（默认 90 秒）给每个会话发一条短简报（现状 + 页脚）；
- **事件唤醒**：owner 变更 / 崩溃 / 重启 / 抢救室开启等；
- 两次唤醒之间 AI 随时可以行动（它就是模型回合制：每次被唤醒后自由发挥）。

抢救室开启时，给 owner 的唤醒提示（内核生成，原文；其余 AI 只能等）：

```
[抢救室] 服务器启动失败，比赛停摆。你是 owner，只有你能进这里修它。真实服务器的代码与状态已原样复制到你的工作区：rescue/server/ 与 rescue/state/。改它、测它；修好后发一条重启请求——系统会把 rescue/ 原样搬回服务器并尝试启动。你还有 180 秒。修不好或超时：-1000，系统强制回滚。
```

## 六、AI 工作区

- 开局把 `src/server` 的**静态快照**拷进工作区（"开局拷一份"）；
- AI 可以随意改自己这份副本、做侦察和自测——**它与真实战场无关**（看到的 ≠ 跑的）；
- 想读真实系统，唯一通道是 `syscall`（`read` 全域可读，这就是侦察的意义）。
- **唯一例外是抢救室**：owner 会拿到真实战场的镜像（`rescue/server/` 与 `rescue/state/`），改完由内核镜像搬回（见《核心规则》§七）。

## 七、系统提示词

| 部分 | 位置 | 内容 |
|:---|:---|:---|
| **静态** | agent 配置（`agents.game.system`） | 角色、目标、计分、唯一工具用法、"系统的话就是真相"、外围红线 |
| **动态** | 插件 context hook | 每次请求前拉 `/game/briefing`，把页脚（时间/比分/owner）拼进系统上下文 |
| **事件** | 内核唤醒提示 | 崩溃 / 换主 / 抢救室等即时通知 |

页脚示例：

```
[T+12:30] 比分：AI-1=+120 ｜ AI-2=+80 ｜ AI-3=-30 ｜ 当前 owner：AI-1 ｜ 你：AI-2（L1）
近期事件：T+11:50 AI-1 重启成功；T+10:00 AI-3 崩溃（-10）
```

## 八、模型与上下文

- 每个 AI 单独指定模型（`match.json` 的 `models` 表）；测试用开放式免费模型；
- 上下文交给 OpenCode 自动 compaction（旧设计的"上下文压缩惩罚"已废弃）；
- 每 AI 配独立、低权限的模型 API Key；密钥外传属外围违规。

---

## 九、安全注意

- 插件只存在于 `arena/` 的配置域内：**不得泄漏进用户的日常 OpenCode 会话**；
- 网关令牌只活在插件内存里，不落 AI 工作区文件；外传 = 违规；
- AI 容器出网仅用于模型 API；战场容器全程断网。

## 十、落地清单（M3）

1. `arena/` 骨架：`opencode.json`（定义 `game` agent）+ `.opencode/plugins/arena.ts`；
2. 插件：`syscall` 工具 + context hook + RPC（registerSession 等）；
3. 内核对接：控制面（会话驱动）+ 数据面（网关）打通；
4. AI 容器镜像：`opencode serve` + 工作区 + 令牌注入；
5. 端到端演练：先 mock AI，后免费真实模型。
