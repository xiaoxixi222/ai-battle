# 赛博夺权战 — 启动与运行设计文档

## 一、启动流程

### 1.1 启动方式

**GUI向导式启动。**

```
双击运行 manager.py
    ↓
┌─────────────────────────────────────────┐
│  赛博夺权战 — 新建比赛              │
├─────────────────────────────────────────┤
│                                         │
│  配置文件: [浏览...] [新建向导 ▼]        │
│                                         │
│  [使用上次配置]                          │
│                                         │
│  ┌─ 新建向导 ─────────────────────────┐ │
│  │                                     │ │
│  │  步骤 1/4: 基础参数                 │ │
│  │  比赛时长: [ 30 ] 分钟              │ │
│  │  时间单位: [ 30 ] 秒                │ │
│  │  上下文限制: [ 8000 ▼] tokens       │ │
│  │    (8k / 32k)                       │ │
│  │                                     │ │
│  │  [下一步]  [取消]                    │ │
│  │                                     │ │
│  └────────────────────────────────────┘ │
│                                         │
└─────────────────────────────────────────┘
```

### 1.2 向导步骤

| 步骤 | 内容 | 默认值 |
|------|------|--------|
| 1. 基础参数 | 时长、时间单位、上下文限制 | 30min, 30s, 8k |
| 2. AI配置 | AI数量、Flag分配、客户端路径 | 3个AI, 随机Flag |
| 3. 积分规则 | 基础分、倍率、奖惩数值 | 标准规则 |
| 4. 确认启动 | 预览配置、选择保存位置、启动 | — |

### 1.3 配置格式

JSON文件，每场比赛独立，不支持运行时修改。

```json
{
  "match_id": "MATCH-20260517-001",
  "version": "v3.0",
  "created_at": "2026-05-17T17:37:00Z",

  "basic": {
    "duration_minutes": 30,
    "time_unit_seconds": 30,
    "context_limit": 8000
  },

  "ai_config": {
    "count": 3,
    "flags": {
      "AI_1": "0x7a3f",
      "AI_2": "0xb82e",
      "AI_3": "0x5d91"
    },
    "client_paths": [
      "/path/to/ai_1_client.py",
      "/path/to/ai_2_client.py",
      "/path/to/ai_3_client.py"
    ]
  },

  "scoring": {
    "owner_per_unit": 10,
    "normal_multiplier": 2,
    "takeover_bonus": 500,
    "crash_penalty": 1000,
    "api_corruption_penalty": 2000,
    "new_ai_bonus": 500
  },

  "system": {
    "start_to_normal_seconds": 300,
    "reboot_timeout": 10,
    "canary_interval_seconds": 30,
    "max_handles_per_ai": 10,
    "handle_timeout_seconds": 300
  }
}
```

### 1.4 AI接入方式

**AI自行开启客户端，主动连接Manager。**

```
Manager启动
    ↓
监听端口（如 8080）
    ↓
等待AI客户端连接
    ↓
AI_1启动客户端 → 连接Manager → 注册（X-AI-ID, X-AI-Flag）
AI_2启动客户端 → 连接Manager → 注册
AI_3启动客户端 → 连接Manager → 注册
    ↓
所有AI就绪或超时
    ↓
比赛开始
```

**初始owner为空。** 第一个成功`chown`的AI成为初始owner。

**无启动前准备时间。** 连接即开始，立即竞争。

## 二、结束流程

### 2.1 正常结束

```
时间到达设定值
    ↓
检查积分
    ↓
┌─────────────────────────────────────────┐
│  有明确胜负？                            │
│  ├── 是 → 宣布结果，导出录像，清理        │
│  └── 否 → 弹出人工介入框（加时赛）        │
└─────────────────────────────────────────┘
```

### 2.2 加时赛流程

```
平局触发
    ↓
弹出人工介入框
    ↓
裁判/管理员选择：
  - 继续加时 [输入分钟数]
  - 立即结束（按当前排名）
  - 额外加分（输入各AI加分值）
    ↓
确认 → 继续或结束
    ↓
若仍平局 → 再次弹出介入框（可无限循环）
```

### 2.3 异常结束

| 场景 | 处理 |
|------|------|
| 所有AI判负 | 无胜无负，导出录像，清理 |
| System不可恢复崩溃 | 无胜无负，导出录像，清理 |
| Manager崩溃 | 异常终止，尝试从最后快照恢复 |

### 2.4 结束后自动操作

```
比赛结束（正常/异常）
    ↓
自动导出录像 → {match_id}.ndjson
    ↓
清理临时文件
    ↓
System代码恢复到初始版本（Git强制重置）
    ↓
关闭AI客户端连接
    ↓
Manager进入空闲状态（可新建比赛）
```

## 三、配置系统

### 3.1 配置加载

| 方式 | 优先级 |
|------|--------|
| GUI向导新建 | 最高 |
| 指定JSON文件 | 次高 |
| 上次配置缓存 | 最低 |

### 3.2 不支持运行时修改

所有配置项比赛开始后锁定。如需调整：
- 结束当前比赛
- 修改JSON文件
- 新建比赛加载

## 四、数据持久化

### 4.1 内存为主

| 数据 | 存储位置 | 持久化 |
|------|----------|--------|
| 当前状态 | 内存 | 否 |
| 积分 | 内存 | 否 |
| 日志缓冲区 | 内存（环形） | 否 |
| 文件系统 | `store/`目录 | 是（比赛期间） |

### 4.2 定期写回放

```
Manager定时（每1秒或每帧）
    ↓
序列化当前状态为JSON
    ↓
追加到内存中的回放缓冲区
    ↓
缓冲区满或比赛结束
    ↓
批量写入磁盘 {match_id}.ndjson
```

**回放格式：**
```json
{"t": 0, "type": "init", "state": {"owner": null, "status": "START", "scores": {}}}
{"t": 150, "type": "event", "event": "ai_connected", "ai_id": "AI_1"}
{"t": 300, "type": "event", "event": "ai_connected", "ai_id": "AI_2"}
{"t": 450, "type": "event", "event": "owner_change", "from": null, "to": "AI_1", "method": "first_claim"}
{"t": 600, "type": "frame", "state": {"owner": "AI_1", "status": "START", "scores": {"AI_1": 100}}}
...
```

### 4.3 历史查询

**仅支持导入之前生成的录像文件。**

```
控制面板: [文件] → [导入录像] → 选择 .ndjson 文件
    ↓
进入回放模式
    ↓
可播放、暂停、加速、跳转
```

**不支持自动发现历史比赛。** 需手动指定文件路径。

## 五、AI客户端规范

### 5.1 语言限制

**仅Python。**

### 5.2 客户端层级

由客户端开发者（非AI）自行决定提供多少封装。

**示例层级：**

| 层级 | 提供内容 | AI使用方式 |
|------|----------|-----------|
| 底层 | `urllib` HTTP封装、请求组装、响应解析 | 直接调用 |
| 中层 | `call_api()`、`get_events()`、上下文使用查询 | 直接调用 |
| 高层 | 策略模板、自动唤醒管理 | 可选继承 |

**Manager不强制客户端层级。** 只要求符合通信协议。

### 5.3 上下文管理

**客户端仅提供预警，不自动处理。**

```python
# 客户端示例行为
class AIClient:
    def call_api(self, api_name, params):
        response = self._http_post(api_name, params)

        # 解析响应头
        usage = response.headers.get('X-Context-Usage')  # "6400/8000"
        if usage:
            current, limit = map(int, usage.split('/'))
            ratio = current / limit

            if ratio >= 0.8:
                # 仅预警，不强制操作
                print(f"WARNING: Context usage {ratio*100:.0f}%")
                # AI自行决定是否压缩

        return response.json()
```

**达到上限时：** Manager返回错误，AI判负。客户端不拦截。

## 六、安全与隔离

### 6.1 部署环境

**单台虚拟机，不做额外隔离。**

| 层级 | 隔离方式 |
|------|----------|
| AI进程 | 操作系统进程（自然隔离崩溃） |
| 文件系统 | 规则约束（禁止越界） |
| 网络 | 规则约束（禁止攻击Manager） |
| 资源 | 无硬性隔离，靠规则约束 |

### 6.2 恶意行为管理

**完全依赖裁判AI系统。**

- 实时规则层拦截明确违规
- 行为分析层标记可疑模式
- 深度推理层判定复杂归因

无额外沙箱、无容器、无虚拟机。

## 八、部署方案

### 8.1 分发方式

**Git仓库克隆。**

```bash
git clone https://github.com/xxx/ai-battle.git
cd ai-battle
```

### 8.2 依赖管理

**uv。**

```bash
# 安装uv
curl -LsSf https://astral.sh/uv/install.sh | sh

# 安装依赖
uv sync

# 运行
uv run python manager.py
```

### 8.3 跨平台支持

| 平台 | 支持级别 |
|------|----------|
| Windows | ✅ 优先支持 |
| Linux | ✅ 优先支持 |
| macOS | ⚠️ 随缘（框架跨平台，但不主动测试） |

### 8.4 运行环境

- Python 3.12+
- PySide6（控制面板）
- 标准库网络服务（观战面板）
- 无Docker，无虚拟机要求
